PulseMind — UI Testing Steps

Follow these steps to test the PulseMind continuous AI workspace from the browser UI. No coding required. Total time: about 10–15 minutes.

Before you start

  1. Ask the developer to start the app (backend + frontend). Open this URL in Chrome/Edge: http://localhost:5173
  2. Confirm the page title shows PulseMind and you see buttons: Run 90s demo sequence, Inject code fault, Spike logs, Deep verify.
  3. Look at the glowing orb in the center. Expected: status text LIVE (not RECONNECTING for more than ~10 seconds). Fail if: stuck on RECONNECTING for more than 30 seconds, or blank/white error page.

Test 1 — First load & live connection P0

  1. Open http://localhost:5173 and wait 5 seconds.
  2. Check the orb label under the circle.
  3. Check metrics row: Cycles, Findings, API.
  4. Check right panel: models should show gemini-3.8-flash and antigravity-preview-09-2026.

Pass: orb = LIVE, Cycles increases over time (or stays > 0), API shows “Gemini live” (or demo fallback if no key).

Fail: page crash, endless RECONNECTING, metrics never update.

Test 2 — Run 90s demo sequence P0

  1. Click the green button Run 90s demo sequence.
  2. Buttons may show “Running…” and disable briefly — that is normal.
  3. Watch the Sentinel timeline on the left for 60–90 seconds.
  4. Scroll the timeline and identify these phases (labels on cards): OBSERVE, REASON, VERIFY, ACT.

Pass: timeline fills with new cards; at least one REASON finding about OrderService / null / division-by-zero or log anomaly; Findings count increases.

Fail: nothing new appears after 90 seconds, or only SYSTEM/heartbeat forever.

Test 3 — Inject code fault P0

  1. Click Inject code fault.
  2. Wait 10–20 seconds.
  3. Look for a timeline card with phase REASON and severity HIGH or CRITICAL.
  4. Read the title/detail — it should mention a code bug (null check, division by zero, etc.).

Pass: REASON card appears with actionable fix suggestion; often followed by ACT and maybe TTS alert.

Test 4 — Spike logs P0

  1. Click Spike logs.
  2. Wait 10–25 seconds.
  3. Look for OBSERVE of type LOG_ANOMALY and a following REASON card.

Pass: log anomaly / timeout / payment pool / latency-related finding appears.

Test 5 — Deep verify (Antigravity) P0

  1. Click Deep verify.
  2. Wait up to 30–45 seconds (this call can be slower).
  3. Find a timeline card with phase VERIFY.
  4. Check the model line on the card footer — should mention antigravity.

Pass: VERIFY card appears with longer remediation / verification text.

Note: if Google API is busy, a demo-fallback verify may appear — still acceptable, but mark as “fallback mode”.

Test 6 — Voice / text command P1

  1. In the right panel Voice bridge, type in the text box: run a deep verify
  2. Click Send (or press Enter).
  3. Look for a VOICE timeline card with the transcript and intent.

Pass: VOICE card shows intent deep_verify, and a VERIFY/ACT follows.

Optional mic test

  1. Click Hold mic command, allow microphone permission, speak clearly: “spike the logs” or “inject a bug”, then click again to stop & send.

Skip if no mic / permission blocked. Use text box instead.

Test 7 — UI layout & mobile P2

  1. Resize browser to phone width (~375px) or use DevTools device mode.
  2. Confirm buttons wrap, orb is visible, timeline still scrollable.
  3. Return to desktop width — layout should return to two columns.

Pass: usable on mobile; no overlapping text; can still click demo.

What “good” looks like (cheat sheet)

UI area Healthy Problem
Orb LIVE + phase OBSERVE/REASON/VERIFY/ACT/IDLE RECONNECTING forever
Timeline New cards after each button click Empty / frozen
Findings metric Increases after inject/demo Always 0 after actions
REASON cards Mentions real bug/log issue + model name No REASON after 30s
VERIFY cards Longer Antigravity-style plan Button does nothing

Quick start for developer (if app is not running)

Backend:

scripts\run-backend.bat or jar on port 8080

Frontend:

cd frontend && npm run dev → port 5173

Tester only needs the UI URL. Backend must already be running.
